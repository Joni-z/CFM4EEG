# LaBraM released-checkpoint finetuning

The pinned original `run_class_finetuning.py` and training engine run directly. The released base checkpoint SHA256 is `7c50583826afac76c4ab18f43d958df40496c8229accc09ed6a227c9bb57c37c`. The wrapper validates coverage and exact equality for every shared model tensor after the original loader. The new classifier and pooling LayerNorm retain native initialization; pretraining-only masked-token head/norm are discarded by the original implementation. A tensor-only serialization bridge avoids legacy metadata incompatibility with modern Torch; it preserves every released model tensor.

For the comparable baseline table, TUEV uses `tuev-shared16-pretrained.json`: accepted common16bipolar arrays with68445/15487/29421rows,200Hz,5s,storedmicrovolts/100. The bridge restoresphysicalmicrovolts before the nativeengine divides100. Its16spatialslots are freshly initialized without any monopolar identity claim. The native23 configuration remains available as a separate protocol and must not populate this shared-cohort table.

CHB-MIT is a new task. Stored Q95 denominators reconstruct physical microvolts; the unchanged author engine divides by100. The sixteen bipolar derivations receive fresh task-specific spatial embeddings in native slots1..16, retaining pretrained CLS/time embeddings and the rest of the backbone. This does not relabel bipolar signals as monopolar electrodes. The original channel table lists CHB bipolar names but maps them to121..136, exceeding the released position table's valid0..128 range; directly using that mapping would fail.

The pretrained settings follow the original pinned README's TUAB finetuning example:50epochs,lr5e-4,AdamWwd.05,warmup5,layerdecay.65,drop-path.1. The single-GPU execution accumulates8 batches of64 to preserve its published8x64globalbatch512; distributed numerical identity is not claimed. CHB and this TUEV execution are explicit task adaptations of the published command. Native validation accuracy selects checkpoint-best. Held-out tests are deferred to the selected checkpoint, and labels/logits/probabilities are saved. Smoke runs use training/validation only.
