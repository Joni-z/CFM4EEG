## Integrity of the record

The ledger is regenerated exclusively from actual run JSON. Duplicate payloads retain all source locations. The grouping key includes configuration and available dataset-manifest metadata; it removes only the seed. Ambiguous repeated-seed artifacts are preserved without choosing their best score. SD is computed only from actual distinct, unambiguous seed records. Aggregation is descriptive and does not certify equal optimization budgets or identical preprocessing.

Published/reference numbers, hand-entered spreadsheets and frozen manuscript cells do not supply missing experimental values. Before a future release or submission, reconcile the desired claims with the source-derived ledger and verify the associated checkpoints and splits.

1. Read the private hub README and remaining-run state.
2. Restore committed history from the bundle and inspect working-tree patches/snapshots; the last runtime is not identical to default `main`.
3. Recover data manifests and the intended checkpoint; do not infer the dataset split from the run name alone.
4. Check the corpus-specific metric and stopped-by field before aggregation.
5. Use the current PPTX / plotting-source index when editing figures.
6. Run a GPU smoke test before any new campaign; preserve all checkpoints.

The closeout reorganizes documentation and light artifacts. It does not revise the frozen manuscript's text/numbers or delete scientific data.
